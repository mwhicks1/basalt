What the arms are

Every arm runs the same instrumented binary; only the source of the generator's choices differs.

  • random — uniform random choices inside libFuzzer's loop (--backend=io-libfuzzer), so coverage is counted identically: the control.
  • fuzz-noramp — coverage-guided FuzzGen from a cold start, with -max_len=65536 -len_control=0.
  • auto-1 — a hybrid: random first, switching once to coverage-guided fuzzing when random's coverage levels off (--warmup-stall=0 --level=φ). The random runs that reached new coverage seed the fuzzer's corpus; it then fuzzes, with fuzz-noramp's settings, for the rest of the budget.
  • back-1 — the same, but the level-off rule applies in both directions (--switch-back --level=φ): when fuzzing levels off it returns to random, and may switch again. libFuzzer's corpus stays in memory, so returning to fuzzing loses nothing.

φ is --level (default 1). With F the tests so far that reached a new feature and H the tests left in the budget, a mode has levelled off when, over a window of tests, it finds new coverage more slowly than min(φ·F/H, rother), where rother is the other mode's find rate when it was last left. φ = 1: staying for the rest of the budget would only about double the finds so far. The rother term hands over only to a mode that was doing better, which keeps the campaign from flip-flopping. The rule is owned by fuzz-run/README.md, “Random warm-up → When to switch”.
